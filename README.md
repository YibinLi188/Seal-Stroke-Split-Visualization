# Seal Stroke Split Visualization

## 古文字结构互动系统

仓库中新增了面向小篆字形研究的协作式浏览器：[打开互动系统](./古文字结构互动系统/)。它展示原始字形、自动候选笔段、释义与来源记录、相似字形和关系图；首批资料来自 v1 实验结果。系统的团队维护说明位于该目录的 `README.md`、`ARCHITECTURE.md` 和 `CONTRIBUTING.md`。

面向金文与小篆字形图片的本地拆笔画工具。项目把单个古文字图像转为骨架路径，分割为独立笔画后，
再把原始前景像素以“每个像素只归属一笔”的方式分配；配套网页以彩色分层动画还原笔画逐步拼回字形的过程。

仓库同时包含算法、16 个内置样例及无需 Node.js 的本地可视化网站。首次启动时，如果结果目录为空，
网站会自动用这些原图生成与当前修改版算法一致的结果。

## 1. 运行

### 依赖

| 依赖 | 要求 | 用途 |
| --- | --- | --- |
| Python | 3.10+ | 本地网站与图像处理 |
| NumPy | `requirements.txt` 中指定 | 数组与骨架计算 |
| Pillow | `requirements.txt` 中指定 | 图像读写 |

安装一次依赖：

```bash
python -m pip install -r requirements.txt
```

### 启动网站

Windows 下可直接双击 [`网站/启动网站.bat`](网站/启动网站.bat)。

也可以在仓库根目录执行：

```bash
cd 网站
python server.py
```

然后打开 <http://127.0.0.1:8766/>。停止服务：在运行服务的终端按 `Ctrl+C`。

> **不能直接双击 `index.html`。** 上传图片需要请求本地 `POST /api/analyze`，只有通过
> `server.py` 启动时才会调用 Python 拆笔画算法。

### 公共在线演示

仓库已通过 GitHub Pages 发布静态演示：
<https://yibinli188.github.io/Seal-Stroke-Split-Visualization/>

在线页面可以被多人同时打开，直接浏览 16 个内置样例、逐笔播放和结果总览。GitHub Pages
不能运行 Python，因此公共页面的上传按钮会提示使用本地完整模式；需要上传分析时请按上面的
`server.py` 方式启动，或把后端部署到支持 Python 的云平台。

### 验证服务

```bash
curl http://127.0.0.1:8766/api/health
```

返回类似 `{"ok": true, "examples": 16}` 即说明网站、样例索引与服务均已就绪。

## 2. 界面与操作

```
┌─ 选择字形 ───────────────┬─ 逐笔回放 ──────────────────────────────┐
│ 上传金文图片              │ 输入字形 / 彩色笔画图层 / 结果总览         │
│ 16 个已拆解样例           │ 播放、暂停、重置、前后单步、速度调节       │
│                            │ 每笔颜色与当前进度                         │
└──────────────────────────┴────────────────────────────────────────┘
```

### 2.1 查看内置样例

左侧“已有样例”包含项目中提供的金文/小篆图片及修改后程序的结果。点击任一条目后，页面显示：

- 原始字形和算法识别到的笔画数；
- 每笔对应的独立像素图层；
- 彩色笔画逐层叠加的动画；
- 输入原图与最终叠加图的总览对照；
- 笔画重叠像素数量，便于核对分配结果。

点击“开始播放”会从第 1 笔重新回放；也可通过笔画标签、上一笔和下一笔定位到某一笔。

### 2.2 分析自己的图片

上传区支持 PNG、JPG、JPEG、WebP，单张最大 16 MB。服务会将图像写入 `网站/runtime_results/`，
调用与内置样例相同的算法，再立即把输出回传给页面。

建议使用白底、深色前景、边缘清晰的单字图片。当前流程按前景像素执行二值化与骨架化；含有大量灰色
噪声、复杂背景或多个字时，拆分质量会下降。

## 3. 算法流程

网页上传与命令行实验复用 `seal_stroke_split` 包，网站模式使用 `split_angle_deg=180.0`，与
“修改后的程序的结果”保持一致。

1. 读取灰度图，并裁剪前景区域。
2. 去除小连通域，使用 Zhang-Suen 方法细化出骨架。
3. 恢复 T 型节点，修正水平/竖直交叉位置并删除交叉冗余点。
4. 把骨架路径切分、合并为候选笔画，并按上到下、左到右、同高横画优先排序。
5. 将每个原始前景像素分配给最近的一条排序后骨架段，禁止跨笔共享像素。
6. 生成单笔图、总览图、叠加图和 `result.json`。

完整修改说明见 [`拆笔画修改/修改操作.docx`](拆笔画修改/修改操作.docx)；代码实现从
[`拆笔画修改/拆笔画_修改/src/seal_stroke_split/pipeline.py`](拆笔画修改/拆笔画_修改/src/seal_stroke_split/pipeline.py) 开始。

## 4. 本地接口

服务仅监听 `127.0.0.1`，不会将上传图片传出本机。

| 方法 | 地址 | 作用 |
| --- | --- | --- |
| `GET` | `/api/health` | 查看服务状态和已加载样例数 |
| `GET` | `/api/examples` | 获取内置样例列表 |
| `GET` | `/api/examples/<id>` | 获取单个样例、笔画颜色与资源地址 |
| `POST` | `/api/analyze` | 上传一张图片并运行拆笔画流程 |
| `GET` | `/media/...` | 返回样例或本次分析生成的图片资源 |

`POST /api/analyze` 使用 `multipart/form-data`，文件字段名为 `image`。分析结果会返回笔画数量、尺寸、
重叠像素数及逐笔 PNG 地址。

## 7. 已知限制

- 当前针对单个、黑色或较深色前景的字形图优化，不是通用 OCR 系统。
- 交叉区域的像素会按最近骨架段单一归属；`overlap_pixel_count` 应为 0，避免动画中多笔颜色互相覆盖。
- 由于输入是图片而不是带笔顺标注的字形数据，笔顺采用几何启发式（上到下、左到右、同高横画优先），不承诺等同于字典笔顺。
- 上传结果保存在本机 `网站/runtime_results/`，重启后不作为内置样例永久展示。
- 首次启动可能需要几秒钟生成 16 个内置样例的结果；生成后会直接复用本地结果目录。
- 页面只提供可视化与回放，不在浏览器内编辑算法输出；需要修改分段策略时应从核心包和测试开始。
- GitHub Pages 是静态托管，只提供内置样例演示；实时上传分析需要 Python 后端。
